# 数据集与共享目录管理手册

## 目录结构约定

- `/data/datasets`：公共数据集区，**统一 data 组只读**，禁止直接往里写实验输出；
- `/data/users/<用户名>`：个人数据区，配额 2TB；
- `/data/checkpoints`：训练 checkpoint 专区，**不备份、定期清理**，重要模型自行转存；
- `/data/models`：公共预训练模型区，只读共享。

## Permission denied 排查

读共享数据集报 `Permission denied` 时：

1. `ls -l` 查文件属主与权限位；
2. `groups` 确认自己是否在 data 组（新账号常见问题，找管理员加组后需重新登录生效）；
3. 他人个人区的文件默认不可读，需要共享时让属主 `chmod g+r` 或拷贝到公共区；
4. 容器以 root 写出的文件普通用户无法删除，参见 Docker 手册的属主问题一节。

## 大文件与数据集传输

- 服务器之间传输走内网 IP，用 `rsync -avP` 支持断点续传，优于 scp；
- 数十万个小文件先 `tar` 打包再传，避免 rsync 遍历开销远大于传输本身；
- 从个人电脑上传大数据集，建议先传到实验室 NAS 再由 NAS 内网同步到服务器；
- 传输前 `df -h` 确认目标盘余量，传完 `md5sum` 抽样核对。

## home 目录与软链接规范

home 目录配额只有 50GB（详见账号配额手册），数据、缓存、conda 环境都应放 `/data/users/<用户名>`，再软链接回 home：`ln -s /data/users/foo/envs ~/envs`。直接把大文件塞 home 会触发配额告警。

## 数据集完整性与登记

公共区新增数据集需在值班群登记：名称、来源、大小、md5 清单。发现数据集损坏（读取报错、md5 不符）先在群里确认是否有人正在重传，避免多人重复下载同一数据集浪费出口带宽。
