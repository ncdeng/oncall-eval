# 训练任务异常排查手册

## 任务被系统杀掉（OOM Killer）

训练进程无报错突然消失，`dmesg | grep -i kill` 出现 `Out of memory: Killed process`，说明是**内存**（非显存）耗尽被系统杀掉。常见于 DataLoader 一次性把数据读进内存、`num_workers` 过多。处理：减小 `num_workers`、用流式读取、分批加载。

## 任务卡住不动（无日志输出）

进程还在但长时间无进度输出。排查顺序：

1. 查看训练日志最后一行停在哪个阶段；
2. 若停在数据加载，多为共享存储 I/O 慢或 DataLoader 死锁；
3. 若停在分布式初始化，多为多机 NCCL 通信未连通，检查 `MASTER_ADDR`、端口、防火墙；
4. `py-spy dump --pid <PID>` 看线程栈定位卡死点。

## 任务报错退出

优先看日志最后的 Traceback。若日志无 error 只有 info，说明不是应用层报错，应转向查进程资源占用与系统层日志（显存方向参见 GPU 显存与占卡排查手册；内存方向见本篇 OOM Killer 相关小节）。

## 分布式训练 NCCL 超时

多卡多机报 `NCCL timeout` 或 `connection closed`，通常是某个 rank 进程挂掉导致其余 rank 等待超时。检查各节点进程是否存活、网络是否连通。
