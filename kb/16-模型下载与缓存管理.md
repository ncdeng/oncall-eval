# 模型下载与缓存管理手册

## HuggingFace 下载失败

服务器直连 huggingface.co 通常超时。标准做法：

1. 设置镜像：`export HF_ENDPOINT=https://hf-mirror.com`（写进 `~/.bashrc`）；
2. 用 `huggingface-cli download <repo>` 下载，比在代码里现拉更可控，支持断点续传；
3. gated 模型（Llama 系列等）需要先在官网申请并 `huggingface-cli login`，镜像站同样识别 token；
4. 报 `401 Unauthorized` 先查 token 是否过期，报 `403` 是没通过模型的使用申请。

## 缓存目录占满 home 配额

HF 默认缓存在 `~/.cache/huggingface`，下几个大模型就能撑爆 50GB 的 home 配额。规范：

- 设置 `export HF_HOME=/data/users/<用户名>/hf_cache`，让缓存落到个人数据区；
- 已经堆积的缓存直接迁移：`mv ~/.cache/huggingface /data/users/<用户名>/hf_cache`；
- 排查 home 超限时，`.cache/huggingface` 永远是第一个该查的目录（参见配额手册）。

## 公共模型区复用

常用底座模型（Qwen、Llama、bge 系列等）统一放 `/data/models`，只读共享。下载新模型前先看公共区有没有，避免同一个 70B 模型被五个人各下一份。需要新增公共模型的在值班群登记，由管理员拉取。

## git lfs 与大文件问题

`git clone` HF 仓库卡在 lfs 拉取：优先改用 `huggingface-cli download`。必须用 git 的场景：`GIT_LFS_SKIP_SMUDGE=1 git clone` 先拉结构，再对需要的大文件单独 `git lfs pull --include="*.safetensors"`（按需替换文件模式）。

## pip / conda 缓存清理

- `pip cache purge` 清 pip 缓存（默认在 `~/.cache/pip`）；
- `conda clean -a` 清 conda 包缓存与解压残留（`~/.conda/pkgs` 或 miniconda 安装目录下）；
- 这两处也是 home 配额的常见大头，清理无副作用（已装环境不受影响）。
