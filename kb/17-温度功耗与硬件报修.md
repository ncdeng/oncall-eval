# 温度功耗与硬件报修手册

## GPU 温度过高与降频

- 卡温超过 85℃ 时 GPU 自动降频（thermal throttling），表现为训练速度骤降但无任何报错；
- `nvidia-smi -q -d TEMPERATURE,PERFORMANCE` 查看当前温度与 `Clocks Throttle Reasons`，出现 `SW Thermal Slowdown = Active` 即在降频；
- 超过 90℃ 触发监控告警：先查该节点风扇转速（`ipmitool sdr | grep -i fan`），再确认机房空调；
- 单卡长期比同节点其他卡高 10℃ 以上，多为该卡风扇或导热硅脂老化，建议报修。

## 机房环境异常

多节点同时高温告警基本是机房空调问题（P0 级）：立即在群里通知所有人暂停新任务，联系机房管理员；必要时的降载停任务由管理员执行（P0 场景可先行停载、事后在值班日志补登记）。单节点功耗超额跳闸后不要自行反复上电，先查供电。

## 硬件故障迹象识别

以下情况优先怀疑硬件而非软件：

- `nvidia-smi` 报 `GPU has fallen off the bus`（Xid 79）：掉卡，断电重启后若复现即报修，反复掉卡的直接停用报修；
- ECC Aggregate 错误计数持续增长（参见 CUDA 驱动手册）；
- 同一节点不同用户的任务都随机崩溃、报错位置无规律；
- 开机自检看不到某张卡（`lspci | grep -i nvidia` 数量不对）。

## 报修流程

1. 值班员收集材料：故障现象描述、`dmesg` 关键片段、`nvidia-smi -q` 输出、复现频率；
2. 在故障登记表登记并 @管理员，由管理员联系厂商售后；
3. 维修周期一般 1-2 周，期间该卡/节点标记停用，跑在上面的任务协调迁移；
4. 返修回来后先跑 24 小时压力测试（`gpu-burn`）确认稳定再放开使用。

## 故障期间的调度调整

节点停用期间：值班员在群里公告可用卡数变化，长任务用户优先获得剩余资源的协调权；紧急 deadline 的同学可申请临时借用其他课题组节点（导师间协调）。
